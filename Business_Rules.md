# Business Rules: Aplikasi Logbook & Ticketing Call Center PDAM

- **BR-001 (Validasi Kontak Seluler):** Nomor kontak pelanggan, jika diisi, hanya boleh berupa karakter numerik (angka) untuk memastikan pemanggilan *keypad* numerik yang tepat di ponsel.
- **BR-002 (Kunci Data Audit BPK):** Data logbook yang statusnya sudah **"Selesai"** dikunci dari aksi penghapusan sembarangan guna menjamin integritas laporan audit BPK.
- **BR-003 (Penomoran Tiket & Auto-Reset):** Nomor tiket digenerate otomatis oleh sistem (Supabase, sebagai satu-satunya sumber data) dengan format `TIK-CC-[YYMM]-[XXXX]`. Sistem wajib mendeteksi pergantian bulan/tahun dan mereset nomor urut ke `0001` pada awal periode baru.
- **BR-004 (Status Mengikuti Tujuan Penanganan):** **[DIPERBARUI]** Status tiket ("Berjalan"/"Selesai") ditentukan oleh `Handling_Types` yang dipilih: jika tujuan penanganan bertanda `otomatis_selesai` (misal "Selesai di Edukasi"), status langsung "Selesai"; jika tujuan penanganan berupa eskalasi (ke Bidang Pelayanan / Kantor Cabang / Lainnya), status "Berjalan" sampai admin mengubahnya manual menjadi "Selesai" setelah pihak terkait mengonfirmasi.
- **BR-005 (Master Data Tujuan Penanganan Dapat Dikonfigurasi):** **[BARU]** Pilihan Tujuan Penanganan (default: Selesai di Edukasi, Eskalasi ke Bidang Pelayanan, Eskalasi ke Kantor Cabang, Lainnya) dikelola admin lewat menu Pengaturan, sama seperti Jenis Interaksi & Kategori.
- **BR-006 (Jejak Perubahan Status):** Setiap perubahan status pada sebuah tiket wajib tercatat otomatis di `Ticket_Status_History`, lengkap dengan waktu perubahan.
- **BR-007 (Backup Wajib):** Sistem wajib menjalankan backup data otomatis (harian dan mingguan) ke email admin dalam format CSV, dan mencatat setiap hasil proses backup.
- **BR-008 (Satu Sumber Data):** Seluruh input tersimpan ke satu database cloud (Supabase) yang sama, tanpa database lokal terpisah, guna mencegah duplikasi nomor tiket dan konflik data.
- **BR-009 (Master Data Tidak Dihapus Permanen):** Jenis Interaksi, Kategori, Tujuan Penanganan, Kecamatan, atau Desa yang sudah pernah dipakai di minimal satu tiket/pelanggan **tidak boleh dihapus permanen** — hanya dinonaktifkan (soft delete), agar data lama tetap valid.
- **BR-010 (Sumber Data Pelanggan):** Data pelanggan (ID, nama, alamat detail, koordinat, golongan) bersumber dari file Excel bulanan yang diunduh admin secara manual dari aplikasi billing pihak ketiga (tidak ada akses API). Perubahan di tengah bulan baru tercermin pada impor bulan berikutnya.
- **BR-011 (Snapshot Data per Tiket):** Nama, alamat, dan No. HP yang tampil di form tiket otomatis terisi dari Data Pelanggan Master saat ID Pelanggan (9 digit) cocok, namun tetap dapat diedit manual per tiket. Perubahan ini adalah snapshot untuk tiket tersebut saja dan **tidak mengubah** data master pelanggan.
- **BR-012 (Verifikasi Wajib Sebelum Impor Diterapkan):** Setiap unggahan file data pelanggan bulanan wajib melalui tahap pratinjau (preview) dan konfirmasi eksplisit admin sebelum diterapkan ke database.
- **BR-013 (Pemisahan Koordinat Otomatis):** Kolom koordinat gabungan pada file sumber wajib dipisahkan otomatis oleh sistem menjadi `latitude` dan `longitude` terpisah saat proses impor diterapkan.
- **BR-014 (Format & Fallback ID Pelanggan):** **[DIPERBARUI]** ID Pelanggan berformat 9 digit angka (2 digit kode kecamatan + 2 digit kode desa + 5 digit kode unik). Jika ID lengkap tidak diketahui, admin **boleh mengisi 4 digit pertama saja** (kode kecamatan + desa); sistem otomatis memetakan ke nama kecamatan & desa dari master data, namun Nama Pelanggan dan Alamat tetap wajib diketik manual, dan koordinat (`latitude`/`longitude`) **dikosongkan** karena tidak ada data pasti untuk kode sebagian ini.
- **BR-015 (Validasi Kecamatan/Desa Saat Impor):** **[BARU]** Jika 2 digit kode kecamatan atau 2 digit kode desa pada `customer_id` di file impor tidak ditemukan di master Kecamatan/Desa yang sudah terdaftar, baris tersebut ditandai **error** pada tahap pratinjau — admin perlu melengkapi data master Kecamatan/Desa lebih dulu di menu Pengaturan sebelum baris tersebut bisa diterapkan.
